# Omi V1.0.1 Windows 使用说明

## 下载与启动

从 [GitHub Releases](https://github.com/ZoeGet/Omi/releases) 的 **Assets** 下载 `Omi-Windows-1.0.1.zip`。不要下载自动生成的 `Source code`，它是源码，不是可运行的软件。

右键压缩包，选择“全部解压”，打开解压后的 `Omi` 文件夹，双击 `Omi.exe`。不要在压缩包内直接运行，也不要单独移动 exe；保留整个 `omi-device` 文件夹和随附许可文件。

本包面向 Windows x64。无需安装 Python、Rust 或 PlatformIO；界面依赖 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。使用 Codex 监控时，还需要安装并运行本机 Codex。软件不会代装或登录 Codex，也不包含设备固件自动升级。

设备必须已安装支持 USB 桌面协议或无线服务的配套固件；默认源码构建不开放这两项能力。开发和升级见[固件文档](https://github.com/ZoeGet/Omi/blob/main/Firmware/README.md)。

## 先连接设备，再使用灯光

**USB：** 使用支持数据传输的 USB 线连接 Omi；打开“设备概览”，选择 USB、对应串口，点击“连接设备”。等界面确认已连接后，在“控制模式”中选择“本地灯光”。

**本地灯光：** 打开“灯光与灯效”，选择 24 个常用色之一，或点击“自定义颜色”；调整亮度、选择常亮/彩虹/呼吸/跑马/扩散/关闭，最后点击“应用灯光设置”。预览是模拟效果，只有收到设备回执才代表设置成功。彩虹使用独立色谱，不使用单个自定义颜色。Codex 监控期间手动灯光被锁定，需先切回本地灯光。

修改后会显示“有未应用修改”，切页不会丢失本次编辑。点击应用后显示等待确认，收到设备成功回执才显示“已应用”；失败会保留编辑供重试。“已应用”表示本次连接收到的命令确认，不是实时读回；断开或切换控制模式后需重新应用。

软件会记住上次成功连接的设备和方式，下次启动尝试恢复连接。短暂拔插或断网时显示自动重连进度，最多五次，可点击“取消重连”；手动断开/取消后，下次启动也不会自动连接，直到你再次主动连接。启动时原 USB 串口不存在，或无线地址/身份已变化时，按提示手动选择或重新查找设备。恢复连接不会自动重发尚未确认的灯光修改；监控会重新取得有效状态。

**Wi-Fi：** 电脑与设备必须处于可互通的局域网。设备已联网后，说“老鼠狒狒”，听到提示音后说“开启配对模式”；在“无线配对”填写设备屏幕的 IP 和六位配对码。配对完成后，回“设备概览”，选择 Wi-Fi、已配对设备并点击“连接设备”。首次配对不要求 USB；设备需要配套的无线/语音固件。不要把六位码、配对凭据或本机数据目录发给别人。

## 开启 Codex 任务监控

仅控制本地灯光时不需要安装监控组件。开启任务屏后，软件会从本机标题索引读取聊天标题，转成可识读的位图发送并显示在 Omi 屏幕上；不发送聊天正文、提示词、工具参数或回复正文。采集器会在本地保存会话标识、工作目录与宿主关联等元数据，详细范围见下文“本地数据与隐私”。

1. 完整解压压缩包。保留 `Omi.exe` 旁的 `omi-device` 文件夹，双击 `Omi.exe`。
2. 打开本机 Codex。在 Omi 首次使用向导中点击“重新检测监控”，核对列出的 Codex 程序；未检测到时可选择实际的 `Codex.exe`。已安装或已收起引导的用户可从“设置”进入，首页不会每次重新展开。
3. 若已连接设备，先在“设备概览”点击“断开连接”，并确认当前不是演示模式，再点击“安装监控组件”。程序会先备份，再合并用户级 Hook；其他工具的 Hook 保留。能明确识别的旧 Omi Python 采集入口会迁移，无法确认归属的处理器会提示冲突并停止。
4. 在 Codex 中审查并信任新的 Omi Hook。CLI 可输入 `/hooks`；桌面版按其 Hook 审查提示操作。安装本身不会自动获得信任。
5. 让 Codex 执行一个普通操作，再回到 Omi 点击“重新检测监控”。看到“已收到真实事件，Codex 宿主关联正常”才代表接入通过。只收到消息事件时，可能仍需一次工具操作确认宿主。
6. 在首页“设备连接”选择 USB 或 Wi-Fi：USB 选择串口，Wi-Fi 选择已配对设备，再点击“连接设备”，连接成功后开启 Codex 监控。尚未配对、换网或待验证时，点击“配对与设备管理”处理。断联或租约结束关灯，语音优先。

不需要额外安装 Python、Rust 或开发工具。需要本机 Codex、WebView2，以及支持相应功能的设备固件。程序不会代装或登录 Codex。

每次启动 Omi 时会检查已安装监控的 Codex 版本目录。同一安装位置存在唯一可迁移的运行版本、且配置和组件校验正常时，会先备份再更新 Omi Hook，提示重新审查信任；检查不代替信任。多个版本、其他已选程序失效或校验异常时按提示手动处理。Codex 在 Omi 运行期间升级后，需重启 Omi 才会再次自动检查。

## 无线连接与重新配对

首次无线连接时，输入设备 IP 后软件会检测已有绑定；也可点击“检测配对状态”。若提示设备已有绑定、本机没有有效凭据，点击“重新配对该设备”，阅读旧电脑凭据失效提示，再用屏幕新码确认；不要反复普通配对。待确认记录先恢复配对确认，已验证的本机记录可直接连接。身份变化时先核对设备和 IP，检测失败不等于未绑定。

屏幕显示 TASK SOURCE UNAVAILABLE 时，打开“连接诊断”查看“连接与监控自检”。依次核对设备连接、组件安装、Hook 事件和任务数据；按提示在 Codex 信任 Hook 并执行一次工具操作，再重新自检。已连接、收到过事件、当前数据有效是不同结论；有效空闲显示 NO ACTIVE TASKS。组件修复在设置执行，不会由自检自动安装或更改信任。

电脑和设备更换 Wi-Fi 后，打开“无线配对”，在“已保存设备”中点击“重新查找设备”。等待原设备身份验证成功、列表地址更新，再点击“无线连接”，不需要配对码。查找最多约一分钟；大型网络、网络隔离或设备被其他客户端占用时可能查找不到。也可展开“更多操作”，点击“修改地址”，输入路由器设备列表中的新 IP，再点击“验证并保存地址”。验证失败会保留原配对记录。USB 或 Wi-Fi 已连接时，页面说明禁用原因；点击“断开当前连接”后再管理配对。

配对与重新配对（需要升级配套固件和语音模型）：设备联网后说“老鼠狒狒”，听到确认音后说“开启配对模式”，屏幕显示新的六位码和当前 IP。电脑与设备处于可互通局域网，在“配对新设备”填写屏幕地址、新码，点击“配对”。换电脑或丢失凭据时，展开“配对帮助”，点击“重新配对已有设备”，确认旧凭据失效提示后填写新码并点击“确认重新配对”。无需 USB，也不需要旧电脑凭据；成功后旧电脑的密钥失效。码限时 5 分钟、最多 5 次尝试，超时/锁定后可再次唤醒并说“开启配对模式”。普通重启不开窗，并可取消未完成的配对、保留旧绑定。窗口期间暂时断开旧无线连接；若提交后没有收到成功确认，已保存设备显示“验证连接”供恢复，不要删除待确认记录；正常已配对设备仅显示连接和查找操作。显示 `PAIR UNREADY` 表示设备未联网或服务未就绪，联网后再说一次。升级前固件不支持此入口，不能只更新上位机。

## 监控状态、托盘与容量

监控默认运行红、等待操作黄、完成绿，五种状态的颜色/亮度/动效可在“监控灯效”修改并保存到设备。同一聊天的新任务接替旧任务；旧未结束轮次及背景问题不再让新任务结束后一直红/黄。当前任务运行显示运行，停止且仍有本任务问题待回复时才显示等待。真实审批和其他聊天的等待仍优先。断联或租约到期强制关灯；来源异常默认绿不代表任务完成。

默认点击右上角 X 会隐藏到系统托盘，设备监控继续运行。单击托盘中的 Omi 图标或右键选择“显示主窗口”恢复；图标也可能在 Windows 的隐藏图标区中。需要真正关闭时，右键托盘图标选择“退出软件”。设置页“关闭窗口时”可选择隐藏到系统托盘或退出软件，选择会保存；退出会先释放设备连接，但不卸载 Codex 采集组件。

可以继续新建 Codex 聊天，累计聊天/磁盘历史没有固定数量上限；历史未自动裁剪，仍受电脑资源限制。当前发给设备的监控视图最多 16 个条目，包含运行、等待、来源未知及保留的最新结束记录；真正超限会显示来源异常。历史累计超过 16 个导致异常的问题已修复，升级时需要更新完整软件包及已安装采集器，并信任新版 Hook。详见 [历史容量排查](https://github.com/ZoeGet/Omi/blob/main/Tools/CodexMonitor/README.md#历史聊天超过设备容量导致来源异常)。

## 本地数据与隐私

为兼容已有安装，数据目录沿用 `OmiPet`，无需改名或删除。采集组件会复制到 `%LOCALAPPDATA%/OmiPet/monitor-runtime/<安装ID>/` 的版本化目录。之后移动解压文件夹不影响已配置的采集器。请不要手动删除这个运行目录。

设置页可重新检测、修复/更新或卸载接入。Codex 更新导致程序路径变化时，重新选择实际程序并修复；Hook 定义变化后按 Codex 提示重新信任。卸载仅移除本程序管理的 Hook 和未修改的运行组件，保留其他 Hook、备份和历史状态；被占用或修改的组件会保留并提示。

备份位于 `%LOCALAPPDATA%/OmiPet/monitor-backups/`。监控元数据默认位于 `%LOCALAPPDATA%/OmiPet/codex-monitor-probe-v2/`，保存会话/轮次/工具调用标识、事件、工作目录、权限模式、派生状态及宿主关联；不保存提示词、工具参数和回复正文。配对凭据位于 `%LOCALAPPDATA%/OmiPet/pairing.sqlite3`。这些目录和配置备份可能含个人路径/标识，不包含在分发包中，也不应直接发到 Issue。

任务标题不写入采集器历史，支持任务屏时仅转为可识读位图经 USB 或已认证 WSS 发往设备。标题索引不可用时回退为会话编号。位图仍包含标题信息，请留意设备摆放位置。

没有新事件时，程序无法判断是未信任、尚未触发还是 Codex 尚未重新加载配置，请按步骤检查。组织策略禁止用户 Hook 时，需要管理员提供允许的接入方式。
