# 无线配对隔离实验

2026-10-16：已接入设备 WSS 配对、上位机六位码输入、凭据持久化和重连身份验证；另有默认关闭的 `OMIPET_WIFI_CONTROL` 隔离入口，承载无线灯光和 Codex 监控。稳定构建默认关闭无线服务，验证范围见下文。

当前重配规则（2026-10-18，需升级固件与语音模型；基本重配流程已实测，异常边界待验）：同一可互通局域网；说“老鼠狒狒”，听到确认音后说“开启配对模式”，屏幕显示当前 IP 和新的六位随机码。首次与已配对设备均由语音主动开放，普通重启不开窗、不清除绑定；重启可取消窗口。每次窗口 5 分钟有效、最多 5 次尝试（含中断），成功/超时/锁定后隐藏，可再次使用唤醒词和命令打开新窗口。旧密钥在新提交前保留，新配对成功后旧密钥失效，仍只绑定一台电脑。输入屏幕新码证明本次配对，不能仅凭网络请求重置身份。USB/语音优先保持不变；NVS 不加密，不执行 eFuse 设置。

语音使用现有离线 MultiNet 入口，ID 1 唤醒，ID 17=`kai qi pei dui mo shi`，只在唤醒后的命令监听状态执行。未联网或服务未就绪时不排队延后开窗，显示 `PAIR UNREADY` 并输出 `[PAIR] open=0 reason=...`，联网后需再说一次。成功请求非阻塞提交到配对维护逻辑，先关闭旧 WSS 再生成新码；配对窗口期间暂停旧密钥的日常连接，避免旧程序占用唯一客户端位置，窗口超时或重启取消后可恢复旧绑定连接。串口日志 `[PAIR] open=1 source=voice paired=... ip=...` 不包含配对码。原 GPIO、VAD、阈值、唤醒音与 20 ms USB 修复不变。

已确认参数：WSS `8443`、最多 1 个无线客户端、TLS/配对步骤 10 秒、日常 I/O 2 秒、4096 字节完整文本帧、每轮密码交换最多 1024 字节。TLS DER 证书/私钥缓冲分别 1024/256 字节，证书日期固定为 2026-01-01 至 2050-01-01；配对后以完整证书 SHA-256 指纹验证身份。服务沿用 ESP-IDF 默认优先级，栈 10 KB。

`Firmware/src/wireless_pairing.cpp` 使用 ESP-IDF HTTP/WebSocket 服务和 Mbed TLS TLS 1.2 传输回调，绝对截止时间限制握手；主循环不运行密码交换，只更新屏幕和连接截止时间。仅设备联网后启动一次，屏幕显示六位码、倒计时和 IPv4 地址；失联时关闭连接并隐藏码，期限不重新开始。首次请求沿用 `pair1`；主动重配使用 `repair1`，同样必须通过完整 PAKE 证明。只有新码证明和提交证明均通过，才可替换已知有效的旧密钥，保留 TLS 证书、Wi-Fi、监控配置及其他 NVS。损坏/未知身份仍拒绝开放，不自动擦除或恢复出厂。

`pairing_exchange.h` 是 Windows 和 ESP32 共用的有序 EC J-PAKE 实现；Windows 通过 `native/pake.cpp` 的小型 DLL 调用本机 SDK 内 Mbed TLS 2.28.7，未修改上游源文件。密码证明绑定四轮消息、角色和本次 TLS 证书指纹；六位码不直接发送到网络，也不使用六位码的普通哈希替代 PAKE。TLS 首次连接的证书只有在 PAKE 确认后才可信，失败不能进入日常认证。

提交顺序：双方完成密码证明 → 电脑先持久保存 pending 凭据 → 设备验证提交证明并保存/读回 NVS → 返回提交证明 → 电脑标记 confirmed。普通配对不覆盖 confirmed 身份；主动重配由独立 `repairs` 表暂存候选，保留原记录，确认后事务提升新凭据并移除本机同一证书的旧地址记录。确认包丢失时点击“验证连接”，优先尝试候选，再尝试原凭据；未确认候选不删除，避免并发提交时丢失恢复密钥。新电脑不需要原凭据，也能凭屏幕新码重配；恢复出厂导致证书变化时同样需明确选择重配并通过新码证明。旧电脑凭据失效后不能自动替换身份。

故障边界：错误码、过期、锁定、提交前断开及电脑候选保存失败不改变设备旧密钥。设备 NVS 写入失败时不预先删除旧记录；若提交已落盘但确认/读回失败，设备可能已使用新密钥，电脑保留候选用于恢复，不能承诺所有报错都等于设备没有提交。身份读取不确定时暂停授权，重启后重新读取；不通过清空 NVS 掩盖存储故障。重配时先断开正在占用 WSS 的旧程序（设备最多一个客户端），双方须网络互通；访客隔离不是重新配对可以绕过的条件。

日常验证使用双方新随机数和已有双向 HMAC 门禁。电脑在发送应用消息之前校验证书指纹。凭据保存在当前用户 `%LOCALAPPDATA%/OmiPet/pairing.sqlite3`；不记录配对码/密钥/原始网络错误，不上传凭据。主动重配是独立显式操作；尚无单独解除绑定/恢复出厂入口。

换网络或 DHCP 改变地址后，在上位机“已保存设备”中点击“在当前网络查找”，或“修改地址”后输入路由器显示的新 IP。两者均先核对原证书指纹，再完成原密钥的双向认证，成功后在 SQLite 事务内迁移地址并确认凭据；不重新配对、不更换设备身份、不修改设备 NVS。失败、取消、凭据并发变化或新地址属于其他已保存身份时拒绝迁移，保留原记录；最后确认丢失的 pending 凭据也可在新地址认证恢复。此流程兼容原无线固件。

`wireless_discovery.py` 仅在用户点击查找时枚举 Windows 在线物理网卡的 IPv4 直连网络，排除 WSL/VMware 等虚拟网卡；保留原 WSS 端口。每个子网不超过 4096 个地址时扫描该子网，更大网络仅使用该接口的邻居缓存；总候选最多 8192 个、24 路并发、扫描预算 45 秒，退出取消排队任务并等待有界网络调用结束。探测只比较 TLS 证书，匹配后另建连接执行完整认证；不会向未匹配证书发送认证消息。未找到时可语音打开配对窗口读取当前 IP，手动更新地址或主动重新配对；访客隔离等网络互通条件仍需满足。屏幕 IP 在配对窗口显示，正常模式不常驻。

无线控制需生成配置时额外指定 `--wireless-control`，并同时开启配对及原 USB 桌面/监控策略。每次 WSS 重连都先校验证书、完成双向 HMAC，再使用无串口前缀的 `?` 发现与原 JSON 协议；首轮配对提交不直接放行控制。网络线程通过单个待处理槽交给主循环中的 `ProtocolSession`，等待沿用 2 秒 I/O 截止时间；主循环不等待网络发送。会话身份、序号去重、5 秒租约、每秒更新和 2 秒/1 次重试沿用原实现。`wss_stream.py` 只适配传输边界，继续使用现有请求器、控制器和监控状态读取。

两条连接独立保活：USB 活动监控优先，无线在后台保持自己的有效快照，USB 释放或断联后可接续；没有备用监控时断联关灯。任一活动监控锁定手动调灯，USB 有效租约也阻止无线手动命令。语音唤醒同时让两条监控输出退出，旧连接快照不能抢回；本地选择与新命令不会重放旧颜色。无线界面显示本连接的确认状态，USB 优先时不等同实际灯色；完整设备状态读回尚未实现。无线仅有通信诊断，音频健康仍需串口采样。

实机验收：设备接 USB 且独立供电 → 备份当前完整 Flash 并校验摘要 → 烧录隔离应用及原 5 MiB 模型 → 检查 `[PAIR] ready=1 paired=0 ip=… port=8443`、`mic`、`queued/dropped`、`task_wdt` → 用户在上位机输入屏幕地址/码 → 检查 `[PAIR] committed=1` 和成功回执 → 断开/重启后“验证连接”，确认不重新显示码。
