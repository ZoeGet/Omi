# Omi 固件开发

本目录为 ESP32-S3 设备固件。项目概览与 Windows 下载见[仓库首页](../README.md)，USB/WSS 协议见[DeviceBridge](../Tools/DeviceBridge/README.md)。

## 硬件与工具链

已验证硬件为自制 ESP32-S3-WROOM-1-N16R8 板，16 MB Flash、8 MB OPI PSRAM。PlatformIO 环境名 `esp32-s3-devkitc-1` 是兼容构建目标，并非实际模组型号。其他板需要核对引脚、内存模式、外设与供电，不能仅按芯片名称判断兼容。

| 项目 | 已验证基线 |
| --- | --- |
| PlatformIO 平台 | Espressif32 6.12.0，固定于 `platformio.ini` |
| 框架 | Arduino + ESP-IDF 4.4.7 |
| Arduino 包 | `3.20017.241212+sha.dcc1105b`（包版本，不是核心语义版本） |
| 语音组件 | ESP-SR v1.2.0，Git 子模块 |
| 模型 | 中文 MultiNet `mn6_cn`；独立 5 MiB 模型分区；WakeNet 关闭 |

在仓库根目录运行以下命令。首次构建会下载 SDK、工具链和依赖，需要网络；设备离线语音本身不依赖网络。

```powershell
git submodule update --init --recursive
pio run -d Firmware -e esp32-s3-devkitc-1
```

构建成功应包含 `firmware.bin` 与 `model.bin`。模型由 `include/voice_command_config.h` 自动同步生成，不能手改构建目录词表。不要删除或手动清理上游 `components/esp-sr` 的文件。

## 伙伴仪表盘

源码界面采用深色伙伴仪表盘：顶部网络、语音和估算电池图标，左侧静态表情，中央大号时钟，右侧温湿度；表情在左侧内容区居中，下方没有文字；温湿度标签与读数各自左对齐。监听页显示“我在听”，配对页显示分组的六位码、地址和无框倒计时。时间无效时继续使用占位符；电池图标仍来自电压估算，不代表新增电量校准。

任务页保留四个固定槽位、160×16 主机标题位图及等待优先的协议语义；运行红、等待黄，状态文字直接显示于卡片底色，无前置圆点或独立黑底。无活动任务显示“暂无活动任务”；来源不可用时按界面文案显示“无任务”，协议状态保持不变，断联恢复本地页，配对显示优先。日常页不再常驻 Wi-Fi 名称，网络状态栏表示设备的 Wi-Fi 状态。

页头使用 Omi、Codex；小号中文为 14 像素单色笔画。字体是随固件编译的 [Omi UI 小字模集](assets/fonts/README.md)，无需联网或完整中文字库。绘制继续使用 20,600 字节静态区域缓冲；标题、数字和状态按变化刷新，运行中的整页切换每次 `update()` 最多传一块，状态 setter 不做屏幕传输。启动首屏完整绘制；未增加循环动画、改变 SPI 频率或主循环音频调度。

此界面需要重新构建、烧录配套固件才能出现在设备上。原生像素测试与构建仅验证软件行为，实机字形可读性、配色、切页过程和语音/USB 并行仍需验收。

| NV3007 SPI | MOSI 11、SCK 12、DC 9、RES 14、CS 10、背光 21；142×428，横屏 428×142，8 MHz |
| AHT20 I²C | SDA 39、SCL 38，地址 `0x38`，100 kHz，外部上拉至 3.3 V |
| WS2812B-2020-V6 | 13 颗，数据 GPIO47，经 330 Ω 到首颗，GRB/800 kHz；电源为 VSYS |
| ICS-43434 I²S | BCLK 5、WS 6、SD 7；当前右声道槽，VDD 3.3 V |
| 电池 ADC | GPIO13；VBAT 经 100 kΩ/150 kΩ 分压，比例 0.6，100 nF 对地 |
| 无源蜂鸣器 | GPIO4 经 1 kΩ 驱动 S8050，10 kΩ 基极下拉，正端 3.3 V；保留 D7 续流二极管 |

以[原理图](../Hardware/Schematic/Omi_Schematic.pdf)核对实物。LCD 的 SDA/SCL 是 SPI MOSI/SCK；背光当前为高电平开启。麦克风 LR 的两颗选槽 0 Ω 电阻只能装一颗，改变装配后重新确认有效声道。蜂鸣器负端不能直连 GPIO，D7 阳极接集电极、阴极接 3.3 V；三极管脚序与器件电流需按实物核验。

灯带 VDD 接 VSYS，低电量/带载压降可能低于其 3.3 V 工作下限，13 颗全白约 468 mA 为估算。不能以代码构建通过代替电池全周期、背光温升和供电裕量验证。电池百分比来自单节锂电电压估算，带载或充电时仅供参考；ADC 连续失败会使旧值过期并显示占位符。

## Wi-Fi、时间与离线运行

首次没有保存 Wi-Fi 配置时，设备会启动配网热点并显示门户地址；使用手机连接热点后，在网页中选择附近 Wi-Fi 并填写密码即可完成配网。

Wi-Fi 现保存最近成功使用的 5 个不同 SSID（NVS，断电保留），同名网络更新密码，第 6 个成功连接的网络替换最久未成功使用的记录。启动优先尝试最近成功的网络；断线后按每组最多 20 秒依次重试，门户开启或超时后仍继续重试。初次启动会先尝试一轮已保存网络，运行中断线保留原 60 秒配网宽限期。升级会迁移驱动中尚存的最后一组凭据；以前已被覆盖的网络需重新配网一次。2026-10-19 实测覆盖旧凭据迁移、旧网恢复及 90 秒音频健康采样；真实多网络自动切换、物理断电持久化和语音动作并行稳定性仍待实机验收。

联网后固件通过 `ntp.aliyun.com`、`pool.ntp.org` 和 `time.nist.gov` 获取时间，按 UTC+8 显示；首次同步失败每 10 秒重试，已同步后每 1 小时重新校时。主循环在音频处理后、UI 绘制前统一刷新一次网络和时间状态。只有 Wi-Fi 已连接且 NTP 已同步时才显示时间；Wi-Fi 断开或 NTP 尚未同步时，时间显示为 `--:--`，日期显示为 `----/--/--`，不会回退到编译时间。

## 温湿度补偿说明 / Sensor Compensation

AHT20 上电初期的读数通常接近环境值。随着 ESP32-S3、LCD 背光、电源区域和灯带持续工作，传感器所在 PCB 区域会升温，导致温度偏高；相对湿度也会因此表现为偏低。

当前固件采用针对本设备实测得到的经验补偿：温度约减 `4 °C`，湿度约加 `9 %RH`。这不是 AHT20 厂家提供的固定参数，只适用于当前 PCB、负载、背光、灯带亮度、供电和外壳条件。若这些条件改变，应重新进行现场校准。

每 5 秒采样一次，读取或校验失败时保留最近有效值并标记过期。上电初始化失败后，原有自动软复位/校准成功会恢复采样资格；当次失败不会发布为有效新数据。

分步采样选项 `OMIPET_AHT20_ASYNC` 默认为 `0`，保留已验证的同步路径。只在独立构建配置中添加 `-DOMIPET_AHT20_ASYNC=1`，可让正常测量的 10 ms 命令间隔和 80 ms 转换等待交还主循环；仍使用 120 ms Busy 超时、5 ms 轮询间隔及相同 CRC、范围检查和补偿。I²C 事务、启动初始化和故障软复位仍为同步操作，因此不是所有路径都无阻塞。模拟总线测试覆盖启动恢复、错误保留旧值、计时回绕和分步采样；是否改善实机音频丢帧及长期稳定性仍待验证，尚未默认启用或刷写。

> **English** — The temperature and humidity offsets are device-specific field calibration values, not sensor-datasheet constants. Recalibrate them if the thermal layout, load, lighting, power source, or enclosure changes.


## 麦克风与 I²S / Microphone and I²S

当前固件使用 ESP32-S3 Arduino 框架内置的 ESP-IDF 旧版 I²S 驱动接口 `<driver/i2s.h>`，没有额外安装 ICS-43434 专用库。驱动直接调用 `i2s_driver_install()`、`i2s_set_pin()` 和 `i2s_read()`。

> **English** — The microphone driver uses the ESP-IDF I²S driver bundled with the ESP32-S3 Arduino framework. No dedicated ICS-43434 library is required.

### 硬件连接 / Hardware mapping

| ICS-43434 信号 / Signal | ESP32-S3 GPIO | 说明 / Description |
| --- | ---: | --- |
| `SCK` / BCLK | `GPIO5` | ESP32-S3 输出位时钟 / Bit clock generated by ESP32-S3 |
| `WS` / LRCLK | `GPIO6` | 字选择时钟 / Word-select clock |
| `SD` | `GPIO7` | 麦克风串行数据输出 / Microphone serial data output |
| `LR` | 由硬件电阻配置 | 决定左/右声道槽 / Selects the left or right I²S slot |

### 当前有效声道 / Active channel

**当前固件明确使用 I²S 右声道槽（`MicChannel::Right`）。**

这是根据当前实物测试确认的：原始双槽数据中只有右声道槽出现非零采样，左声道槽为零。因此 `src/main.cpp` 会显式调用：

```cpp
OmiPetAudio::microphone.begin(
    OmiPetAudio::kMicDefaultSampleRateHz,
    OmiPetAudio::MicChannel::Right);
```

对应代码位于 [`src/main.cpp`](src/main.cpp) 和 [`include/ics43434_mic.h`](include/ics43434_mic.h)。如果更换 PCB、修改 `LR` 电阻或更换麦克风装配方向，需要重新确认有效声道，并同步修改 `MicChannel::Right`。

> **English** — The current firmware explicitly uses the **right I²S slot** (`MicChannel::Right`). This was verified on the assembled hardware because the right slot contains non-zero samples while the left slot remains zero. Re-check the slot if the PCB `LR` configuration or microphone assembly changes.

### 当前音频参数 / Current audio parameters

- 采样率：`16 kHz` / Sample rate: `16 kHz`
- 接收槽宽：`32-bit` / Receive slot width: `32-bit`
- 有效数据：ICS-43434 的 `24-bit` 数据，固件右移 8 位后用于音量分析 / 24-bit microphone data shifted by 8 bits for level analysis
- 音量窗口：约 `50 ms` / Level window: approximately `50 ms`
- 输出指标：`avg_abs`、`rms`、`peak`、`noise`、`threshold`、`speech`


### 语音交互状态 / Voice interaction state

当前固件使用 `16 kHz`、`16-bit`、单声道 PCM，将每次 `160` 个采样点的输入帧送入 AFE；AFE 以约 `512` 个采样点的输出帧驱动中文 MultiNet `mn6_cn`。词表包含自定义入口“老鼠狒狒”（ID `1`）、亮度（ID `2/3`）、颜色与动效（ID `4–16`）及“开启配对模式”（ID `17`）。识别到入口后，状态机播放约 `180 ms` 的三段式确认反馈，进入最长 5 秒的 `LISTENING` 等待已配置的灯带或配对命令，同时用独立的白色跑马灯表示已唤醒；命令执行或等待超时后结束这一临时提示。

### 灯带颜色与动效 / LED Colors and Effects

唤醒后说出颜色或动效命令即可切换灯带。颜色命令会保留原本的本地动效，不会强制切换成常亮；唤醒期间的白色跑马灯是独立提示，不会把后续“蓝色灯光”变成蓝色跑马灯。彩色灯光使用彩虹动效，呼吸灯、跑马灯和扩散灯由主循环以非阻塞方式推进，使用约 `12 ms` 的时间驱动帧。三个由命令启动的动效默认使用纯色：呼吸灯为纯蓝、跑马灯为纯绿、扩散灯为纯红；动画只改变亮度，不把其他颜色混入当前颜色。跑马灯和扩散灯始终保留全灯带底光，并用连续渐变高光移动，避免灯珠逐颗跳变或完全熄灭。支持的动效说法包括“彩色”“彩色灯光”“彩色灯”“呼吸灯”“跑马灯”“扩散灯”；颜色命令支持“红色灯光/红色灯”等表达；还支持“开灯”“开启灯光”“一直亮”“关灯”和“关闭灯光”。亮度命令仍以 `16/255` 为步长调整全局亮度，“调亮一点/调暗一点”中的“调”使用拼音 `tiao`。

> **English** — After the custom wake entry, use colorful lights, breathing lights, running lights, or expanding lights. Color commands keep the active effect instead of forcing solid mode. The default effect colors are pure blue for breathing, pure green for running lights, and pure red for expanding lights; animation changes brightness without mixing hues. Running and expanding effects keep a base light on every pixel and add a smooth moving gradient. The brightness commands use `tiao` for 调, as in `tiao liang yi dian` and `tiao an yi dian`.

AFE 和 I²S 始终持续运行，但 VAD 只在检测到语音以及语音结束后的 `1.2 s` 尾窗内调用 MultiNet；这样避免待机时持续推理造成 CPU 调度和看门狗风险，同时尽量保留词尾。该门控策略不会承诺每次都在说话过程中返回，MultiNet 本身仍可能需要积累判定窗口。

> **English** — The firmware uses `16 kHz`, `16-bit`, mono PCM. It feeds `160`-sample input frames into AFE, which produces approximately `512`-sample frames for Chinese MultiNet `mn6_cn`. The current list has 47 phrases across command IDs 1–17: wake entry, brightness, colors/effects, and opening pairing mode. After detection, the state machine plays an approximately `180 ms` three-phase acknowledgement and listens for configured phrases such as “亮一点”, “暗一点”, or “开启配对模式”; this is finite-vocabulary recognition, not open-ended speech understanding.

I²S and AFE remain active continuously, while VAD gates MultiNet detection to speech activity plus a `1.2 s` hangover. This reduces idle inference load and watchdog risk while preserving phrase endings; it does not guarantee that MultiNet returns before the speaker finishes a phrase.

确认音播放期间以及结束后的 200 ms 内，VAD 会暂时抑制语音状态更新，但 I²S/PCM 仍持续采集，避免蜂鸣器回采触发语音开始事件。

> **English** — During the acknowledgement tone and for 200 ms afterward, VAD state updates are temporarily suppressed while I²S/PCM capture continues, preventing buzzer feedback from triggering speech-start events.

## 语音技术栈与唤醒词架构 / Voice Stack and Wake Phrase Architecture

### 技术栈 / Technology stack

当前语音功能采用 **Arduino 应用层 + ESP-IDF 底层 + ESP-SR 语音组件**，不是只依赖 Arduino 库的纯软件实现：

| 层级 / Layer | 当前实现 / Current implementation |
| --- | --- |
| 构建系统 / Build system | PlatformIO，`framework = arduino, espidf` |
| 应用逻辑 / Application logic | Arduino `setup()`/`loop()`、GPIO、灯带、蜂鸣器、UI 和状态机 |
| 音频底层 / Audio layer | ESP-IDF 旧版 I²S 驱动 `<driver/i2s.h>`，驱动 ICS-43434 |
| 语音前端 / Speech front end | ESP-SR AFE，负责音频预处理、AGC 和 VAD |
| 命令识别 / Command recognition | ESP-SR v1.2.0 中文 MultiNet `mn6_cn` |
| 模型存储 / Model storage | `model` 分区中的 SPIFFS 模型镜像 |
| 内存与芯片 / Memory and chip | ESP32-S3-WROOM-1-N16R8，OPI PSRAM，模型和 AFE 缓冲优先使用 PSRAM |

Arduino 负责设备业务和主循环；ESP-IDF 提供 I²S、FreeRTOS 调度和底层硬件接口；ESP-SR 提供 AFE、MultiNet 接口和语音模型。三者是同一份固件中的分层协作关系，不是互相替代的三套方案。

> **English** — The voice feature uses an **Arduino application layer + ESP-IDF low-level APIs + ESP-SR speech components**. Arduino handles `setup()`/`loop()`, device behavior, LEDs, buzzer, UI, and state transitions. ESP-IDF supplies I²S, scheduling, and hardware-level services. ESP-SR supplies the AFE, VAD, MultiNet interfaces, and speech models. This is an Arduino-based application built on the ESP-IDF component layer, not an Arduino-only library implementation.

### 音频处理流程 / Audio processing pipeline

```text
ICS-43434 I²S
    ↓
ESP-IDF I²S RX（GPIO5/GPIO6/GPIO7，16 kHz，32-bit slot）
    ↓
右声道槽提取与 PCM16 转换
    ↓
160-sample PCM frame queue
    ↓
ESP-SR AFE（持续 feed/fetch，包含 VAD）
    ↓
VAD 语音窗口 + 1.2 s 尾窗门控
    ↓
ESP-SR MultiNet `mn6_cn`
    ↓
命令 ID → 唤醒状态机、灯带业务或本机配对请求
```

I²S、PCM 队列和 AFE 会持续运行，但 MultiNet 只在检测到语音活动或最近 `1.2 s` 的语音尾窗内进行判定。门控使用 `main.cpp` 的 RMS、自适应噪声底与连续窗口迟滞；AFE 自带 VAD 虽开启，但不是 `allowDetection` 的直接输入。这样可以避免空闲时持续运行 MultiNet 引起 CPU 调度压力和看门狗风险，同时尽量保留词尾音频。

### “老鼠狒狒”如何实现 / How “老鼠狒狒” is implemented

“老鼠狒狒”是中文 MultiNet 命令词表中的自定义拼音短语：

```text
1 lao shu fei fei
```

个人配置位于 `include/voice_command_config.h`。构建前，`scripts/generate_model.py` 会先解析这个文件，将全部命令生成到当前构建目录的 `multinet_commands_cn.txt`，再把词表复制到 `target/fst/commands_cn.txt`，生成并加入 PlatformIO 的 `model` 分区镜像。运行时，`src/multinet_command_recognizer.cpp` 会通过 ESP-SR 的命令词 API 注册同一组拼音和命令 ID，因此应用固件与模型使用同一份配置。

识别到命令 ID `1` 后，主循环将它解释为自定义唤醒入口：

1. 清空上一段 AFE/MultiNet 上下文；
2. 通知 `VoiceController` 进入 `LISTENING`；
3. 播放非阻塞双音确认反馈；
4. 在 5 秒监听期内接受 ID `2–17` 的已配置命令；
5. ID `2/3` 调整亮度 `16/255`，ID `4–16` 控制颜色/动效，ID `17` 请求限时配对窗口；命令完成或超时后回到持续监听。无线功能未启用或未就绪时，配对请求返回 `PAIR UNREADY`。

命令词的唯一修改入口是 `include/voice_command_config.h`。修改或新增数组项即可维护唤醒词、同义表达和后续命令；不要直接修改构建目录内的 `multinet_commands_cn.txt`，也不要修改自动生成的 `include/generated_multinet_commands.h`。构建检查会拒绝空配置、重复短语、非正 ID、非法拼音、超过 MultiNet 长度/数量上限的配置，并确保当前运行时必需的 ID `1–17` 与头文件一致，且 ID `1` 只有一条短语。

更换或新增步骤：编辑 `include/voice_command_config.h` → 修改/增加 `{命令ID, "无声调拼音"}` → 重新构建 → PlatformIO 自动同步词表、生成运行时表并把 `model.bin` 加入烧录列表 → 将应用固件和模型分区一起烧录 → 查看 `[ASR] continuous experiment wake_id=1 phrase=...` 日志并实测。新增命令词会自动注册，但要让设备执行新的业务动作，还必须在 `src/main.cpp` 中为该命令 ID 增加业务分派；配置入口不会凭空生成未实现的业务逻辑。

因此，“唤醒词”在当前固件中准确的技术名称是：**MultiNet 自定义命令词入口**，而不是独立的 WakeNet 唤醒模型。

> **English** — “老鼠狒狒” is not a WakeNet model name and is not presented as an official wake word. It is registered as the custom Chinese MultiNet phrase `lao shu fei fei` with command ID `1`. The personal configuration entry is `include/voice_command_config.h`; the build synchronizes every configured phrase to the model input, validates limits and IDs, generates the runtime table, and adds the model image to the PlatformIO flash list. New phrases are registered automatically, but a new command ID still needs a corresponding business handler in `src/main.cpp`. Changing the tone-free pinyin requires rebuilding and reflashing both the application and the model partition, followed by recognition testing; it is not a runtime setting and arbitrary phrases are not guaranteed to work reliably. The accurate technical description is **a MultiNet custom command entry used as an experimental wake trigger**, not a standalone WakeNet model.

### 为什么不用现成 WakeNet / Why the supplied WakeNet model is not used

WakeNet 是专门的唤醒模型，但当前 ESP-SR 模型包中的现成模型对应固定唤醒短语，例如 `wn9_hiesp` 对应 `Hi ESP`。把配置中的字符串改成“老鼠狒狒”，不会改变神经网络已经训练好的识别目标；真正的自定义 WakeNet 需要与目标短语匹配的定制模型，并且还要重新完成模型打包、容量确认、误唤醒率和漏唤醒率验证。

本项目采用自定义入口短语，目前没有与“老鼠狒狒”匹配的定制 WakeNet 模型。当前配置明确关闭 WakeNet：`CONFIG_USE_WAKENET=n`，运行时 AFE 配置也设置 `wakenet_init = false`。

选择 MultiNet 自定义命令词作为实验入口，是因为它允许我们在现有中文 `mn6_cn` 模型上注册自己的拼音短语，可以在没有定制 WakeNet 模型的情况下实验离线入口。代价是 MultiNet 不是低延迟专用唤醒引擎：早期词表短测中，“老鼠狒狒”在语音结束后曾等待约 `1.1–1.3 s`；当前 47 词模型的延迟尚未完成统计，并且仍需继续验证误识别、误触发和长期稳定性。

> **English** — WakeNet is a dedicated wake-word model, but the bundled model is trained for fixed phrases such as `Hi ESP`. Changing a configuration string does not retrain the neural network. A real custom WakeNet phrase requires a matching custom model, followed by model packaging, capacity checks, false-trigger testing, and missed-wake testing. Because this project does not currently have a custom “老鼠狒狒” WakeNet model, WakeNet is explicitly disabled. MultiNet custom commands provide a workable offline experimental entry, but they are not a low-latency dedicated wake engine; an earlier phrase-list test observed about `1.1–1.3 s` after speech ended. The current 47-phrase model still needs latency and long-run statistics.

### 关键构建文件 / Important build files

- `platformio.ini`：声明 Arduino + ESP-IDF 双框架、PlatformIO 环境和模型预构建脚本。
- `CMakeLists.txt`：ESP-IDF 工程入口。
- `src/CMakeLists.txt`：注册固件源文件并声明 `esp-sr` 组件依赖。
- `sdkconfig.defaults`：启用 AFE、中文 MultiNet、模型分区、16 MB Flash 和 OPI PSRAM，并明确关闭 WakeNet。
- `components/esp-sr`：ESP-SR v1.2.0 子模块，提供 AFE/MultiNet 头文件、库和模型工具。
- `include/voice_command_config.h`：个人语音命令配置入口；集中维护命令 ID 和无声调拼音短语，ID `1` 为唤醒词，ID `2/3` 为亮度，ID `4–16` 为颜色和动效，ID `17` 为语音开启配对模式。
- `include/led_controller.h`、`src/led_controller.cpp`：分离的 WS2812B 硬件缓存 `Strip` 和非阻塞动画控制器 `EffectController`。
- `scripts/check_multinet_commands.py`：构建前解析个人配置、同步词表、校验命令 ID/重复短语/容量，并生成 `include/generated_multinet_commands.h`。
- 构建目录的 `multinet_commands_cn.txt`：自动生成的模型输入，不纳入版本管理；唯一配置入口仍是 `voice_command_config.h`。
- `scripts/generate_model.py`：将 ESP-SR 模型和项目词表打包成 `model.bin`，并将其加入 PlatformIO 烧录流程。

上述文件共同组成语音构建入口；AFE、MultiNet 和独立模型分区均为当前实现所需。
